# Power BI: how to open, check and save the dashboard

The dashboard is a **Power BI Project** (`powerbi/EcommerceSales.pbip`). It was generated by script
(`powerbi/build_project.py`) and then opened in Power BI Desktop 2.159 (the version installed on this computer) to test it.
The model (tables, relationships, date table, 26 DAX measures) is in TMDL files and the report (3 pages, 34 visuals) is in PBIR files.

## 1. Settings in Power BI Desktop (one time)

1. **Preview features.** Go to **File > Options and settings > Options > Preview features**. Microsoft's documentation
   (updated September 2026) says that the project format (PBIP), the TMDL model format and the PBIR report format are now generally available,
   so on version 2.159 you should not need to turn anything on. If the project does not open, or **Save as** does not offer
   "Power BI project", look for these options in that list and turn them on, then restart Power BI Desktop:
   - Power BI Project (.pbip) save option
   - Store semantic model using TMDL format
   - Store reports using enhanced metadata format (PBIR)
2. **Map visuals (needed for the state map on page 3).** Go to **File > Options and settings > Options > Global > Security** and
   turn on **Use Map and Filled Map visuals**. Restart if asked. Without this, the map shows the message
   "Map and filled map visuals are disabled". All other visuals work without it.

## 2. Open the project and load the data

1. Double-click `powerbi/EcommerceSales.pbip` (or open it from Power BI Desktop: **File > Open report > Browse**).
2. The first time, the model has no data yet. You see two yellow or grey banners:
   *"One or more relationships have been modified and need to be refreshed manually"* and
   *"Some of the tables have incomplete or no data"*. Click **Refresh now** on each banner (twice). Loading about 19 MB of CSV takes
   about one minute.
   **Click each banner only once and wait until it finishes.** If you click **Refresh now** again while the data is still loading, Power BI can show
   a "Load" error such as *"8 queries are blocked ... dim_product: A cyclic reference was encountered during evaluation"*. That is two refreshes
   running at the same time, not a problem in the model. Close the dialog, close Power BI without saving, open the project again and click once per banner.
3. **Data folder parameter.** The data comes from the CSV files in `powerbi/data/`. The folder is a Power Query parameter called
   `DataFolder`. It is set to the folder of this computer (`D:\projects\Ecommerce_Sales_Analytics\powerbi\data`).
   If you moved the project: **Home > Transform data > Edit parameters**, type the new `powerbi\data` folder, click OK, then **Refresh**.
4. To rebuild the whole project files: `.venv\Scripts\python powerbi\build_project.py` (close Power BI Desktop first).

## 2b. The data folder `powerbi/data/` is NOT in git: regenerate it

The 8 model CSV files (about 19 MB) are made by script and are listed in `.gitignore` (`powerbi/data/`). A fresh clone of the
repository has no `powerbi/data/` folder, so the project shows no data until you make it. How:

1. Make the inputs (only if you do not have them yet). Run these from the project root, with the Docker containers started where noted:
   - `data/processed/*.parquet`: run notebook `notebooks/01_data_cleaning.ipynb` (needs the pipeline export from
     `pipeline_ingest/`, see `pipeline_ingest/README.md`; the notebook also loads `analytics_db`, so start the PostgreSQL container first).
   - `sql/outputs/*.csv`: run `.venv\Scripts\python sql\run_all_queries.py` (needs the PostgreSQL container with `analytics_db`).
2. Export the model files:
   ```
   .venv\Scripts\python powerbi\export_model_data.py
   ```
   It writes `dim_date.csv`, `dim_state.csv`, `dim_customer.csv`, `dim_product.csv`, `fact_orders.csv`, `fact_order_items.csv`,
   `cohort_retention.csv`, `top_customers.csv` and `low_performers.csv` to `powerbi/data/` (it prints the control numbers
   that the DAX measures must match: revenue 13,494,400.74, 98,199 orders, AOV 137.42, 2,887 repeat customers).
   It needs only the Parquet files and the SQL result files, not Docker.
3. Open `powerbi/EcommerceSales.pbip` and click **Refresh now** (section 2).

If you saved `powerbi/dashboard.pbix`, the data is already inside it. You can open the pbix without the CSV files, but **Refresh**
needs them (or a changed `DataFolder` parameter).

## 3. Apply the theme (optional, 30 seconds)

**View > Themes > Browse for themes**, choose `powerbi/theme.json`. It sets the colors (blue and orange first), the background and the fonts.

## 4. What is in the report

| Page | Content |
|---|---|
| **Sales Overview** | Slicers: date range, product category, customer state. KPI cards: Total Revenue, Total Orders, AOV, MoM Growth % (last full month), Revenue YTD. Charts: revenue by month, MoM growth by month, orders by month, AOV by month, top 10 states by revenue |
| **Customers** | Same 3 slicers. Cards: Active Customers, Customers with 2+ Orders, One-time Customers, Repeat Customer %. Charts: new and repeat customers by month, returning customers share, cohort retention matrix (Q11), customers by RFM segment (Q12), top customers table (Q13) |
| **Products & Delivery** | Same 3 slicers. Top 10 categories by revenue, Pareto line (running share of revenue), customer states (map), average review by delivery delay, share of low reviews by delay, low performers table (Q8) |

The three slicers are synchronised: a choice on one page applies to the other pages.
Monthly charts show the full months 2017-01 to 2018-08 only (visual filter), because 2016 and 2018-09 have very few orders.

Things to know when you click around:
- The **category slicer** changes revenue and order measures. It does not change review, delivery and customer measures.
- The **cohort matrix** is all-time (from Q11) and does not react to the slicers.
- The **top customers** and **low performers** tables are results of Q13 and Q8 (all time). The state slicer filters the customer table, the category slicer filters the low performers table.
- **Known limit of the state map.** With map visuals enabled, the map highlights the states and responds to the slicers, but in Power BI Desktop 2.159
  it does not shade the states by revenue (all of Brazil gets one colour). Two ways of setting the colour in the report file were tried and neither changed it.
  The revenue by state is shown as a bar chart on page 1 (top 10 states). To shade the map yourself: select the map, and drag `Total Revenue`
  (table `fact_order_items`) into the **Color saturation** well in the Build visual pane.
- **Optional:** colour the cohort matrix like a heat map: select the matrix, **Format visual > Cell elements > Background color > fx**, choose "Gradient" on `Cohort Retention %`.

## 5. The saved .pbix

`powerbi/dashboard.pbix` (6.4 MB, data included) is saved and committed. You can open it directly, without the `powerbi/data/` CSV files.
It was saved from the project in this folder, so it has the same 3 pages and 28 measures.

To make a new one: **File > Save as**, choose the file type **Power BI files (*.pbix)** (the default can be "Power BI project"), name it
`dashboard.pbix`, and save it in the `powerbi` folder. Check the size before you commit it.

Notes:
1. A pbix contains the data, so the `DataFolder` parameter is only needed when you click **Refresh**.
2. Keep the project too. If you save the project again from Desktop, Desktop rewrites the TMDL and PBIR files in its own format
   (it adds `lineageTag` ids and more report settings). That is fine, but `build_project.py` would overwrite your changes if you run it again.
